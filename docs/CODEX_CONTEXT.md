# RadishDeck — контекст разработки

## Источники истины

VISION.md (v3), ARCHITECTURE.md (v3) и DESIGNER_SPEC.md определяют
целевое приложение. Остальные документы уточняют их и не должны вводить
противоречащие ограничения. При обновлении требований синхронизировать
зависимые документы.

RadishDeck — визуальный WYSIWYG-конструктор панелей управления инфраструктурой.
Desktop создаёт. Renderer отображает. Server выполняет. Web показывает созданное.

Целевая модель элемента: Layout, Content, Appearance, Behavior, Action.
Canvas и Device Profiles определяют рабочую область и отображение.
Desktop Preview и Web Runtime используют один Renderer.

Документация будущих возможностей не подтверждает их наличие в коде.
Исторические записи описывают соответствующие версии, а не текущую архитектуру.
Перед изменениями проверять код, версию и ограничения задачи.
Не создавать второй Renderer и не менять формат Deck без необходимости.
После реализации выполнять проверки и сборку, обновлять документацию и CHANGELOG.
