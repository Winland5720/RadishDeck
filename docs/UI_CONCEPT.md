# RADISH DECK

# UI CONCEPT

Версия: Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

Этот документ описывает принципы интерфейса Radish Deck.

Главная цель:

Создать удобный интерфейс управления компьютером.

Не цель:

-   сделать красивую картинку;
-   перегрузить интерфейс эффектами;
-   копировать другие продукты.

------------------------------------------------------------------------

# 2. Главный принцип

Интерфейс должен отвечать на три вопроса:

1.  Что сейчас происходит?
2.  Что я могу сделать?
3.  Какой будет результат?

Каждый элемент должен иметь:

Состояние

-   

Действие

-   

Результат

------------------------------------------------------------------------

# 3. Основные интерфейсы

Radish Deck имеет два интерфейса:

## Desktop Application

Главное приложение Windows.

Используется для:

-   настройки;
-   управления;
-   создания страниц;
-   настройки элементов;
-   запуска сервера.

## Radish Deck Client

Удалённый интерфейс.

Используется для:

-   просмотра страниц;
-   управления;
-   получения состояния.

------------------------------------------------------------------------

# 4. Desktop UI

Главное окно приложения:

Header

Navigation

Workspace

Properties

Status Bar

------------------------------------------------------------------------

# 5. Navigation

Основные разделы:

## Dashboard

Общее состояние системы.

Показывает:

-   сервер;
-   подключенные клиенты;
-   состояние ПК;
-   события.

## Pages

Управление страницами:

-   Home
-   PC
-   Sound
-   Apps
-   System
-   Docker

## Elements

Библиотека элементов:

-   Button;
-   Text;
-   Image;
-   Indicator;
-   Widget.

## Actions

Список действий:

-   запуск программы;
-   выключение ПК;
-   PowerShell команда;
-   управление звуком.

## Plugins

Расширения системы:

-   Docker;
-   OBS;
-   Discord.

## Profiles

Наборы настроек:

-   Work;
-   Gaming;
-   Admin.

## Settings

Настройки:

-   Server;
-   Network;
-   Security;
-   Interface.

------------------------------------------------------------------------

# 6. Client UI

Client должен быть простым.

Основная задача:

Быстро выполнить действие.

Не перегружать:

-   настройками;
-   редактированием;
-   служебной информацией.

------------------------------------------------------------------------

# 7. Элементы интерфейса

Каждый элемент имеет:

-   Appearance;
-   State;
-   Action;
-   Properties.

------------------------------------------------------------------------

# 8. Button

Кнопка должна показывать:

-   название;
-   действие;
-   состояние.

Пример:

Docker

Running

\[Restart\]

------------------------------------------------------------------------

# 9. Indicator

Индикатор показывает состояние.

Примеры:

CPU 45%

Docker Running

------------------------------------------------------------------------

# 10. Widget

Виджет показывает данные:

-   CPU;
-   RAM;
-   температура;
-   сеть.

------------------------------------------------------------------------

# 11. Layout

Интерфейс строится через Grid.

Не использовать:

фиксированные пиксели.

Использовать:

-   grid_x;
-   grid_y;
-   grid_width;
-   grid_height.

------------------------------------------------------------------------

# 12. Размеры элементов

Поддерживаются:

-   1x1;
-   2x1;
-   1x2;
-   2x2.

Размер должен быть одинаковым для:

-   Desktop;
-   Web;
-   Mobile.

------------------------------------------------------------------------

# 13. Состояния элементов

Элемент может иметь состояние.

Button:

-   Enabled;
-   Disabled.

Docker:

-   Running;
-   Stopped;
-   Error.

Application:

-   Running;
-   Closed.

------------------------------------------------------------------------

# 14. Цвета и стиль

В Alpha главное:

-   читаемость;
-   удобство.

Не требуется:

-   сложные анимации;
-   эффекты;
-   темы.

------------------------------------------------------------------------

# 15. Финальный стиль

В Beta можно добавить:

-   тёмную тему;
-   красные акценты;
-   фирменную редиску;
-   дополнительные ассеты.

Стиль не должен мешать работе.

------------------------------------------------------------------------

# 16. Ошибки дизайна

Запрещено:

-   огромные кнопки;
-   интерфейс похожий на сайт;
-   много декоративных элементов;
-   скрытые действия.

------------------------------------------------------------------------

# 17. UX правило

Любое действие должно быть понятным:

Что нажал?

Что произошло?

Что изменилось?

------------------------------------------------------------------------

# 18. Главная идея UI

Radish Deck --- это инструмент.

Не презентация.

Хороший интерфейс:

-   показывает состояние;
-   даёт контроль;
-   экономит время.
