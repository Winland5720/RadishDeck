# RADISH DECK

# PROJECT STRUCTURE

Версия:

Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

Этот документ описывает структуру проекта Radish Deck.

Главная цель:

Создать понятную и масштабируемую структуру, которая поддерживает
развитие проекта от Alpha до Release 1.0.0.

------------------------------------------------------------------------

# 2. Общая структура

На текущем этапе:

    RadishDeck

    │
    ├── README.md

    ├── CHANGELOG.md

    ├── .gitignore

    │
    ├── assets

    │
    ├── docs

    │
    └── src

------------------------------------------------------------------------

# 3. Документация

Папка:

    docs/

Содержит:

-   архитектуру;
-   API;
-   правила разработки;
-   описание систем;
-   дорожную карту.

Документация не содержит исходный код.

------------------------------------------------------------------------

# 4. Assets

Папка:

    assets/

Используется для:

-   логотипов;
-   иконок;
-   изображений;
-   ресурсов интерфейса.

Структура:

    assets

    ├── branding

    ├── icons

    └── images

------------------------------------------------------------------------

# 5. Source Code

Основной код находится:

    src/

Структура:

    src

    │

    ├── RadishDeck.Core

    │

    ├── RadishDeck.Desktop

    │

    ├── RadishDeck.Server

    │

    └── RadishDeck.Infrastructure

Core содержит чистые модели домена в `src/RadishDeck.Core/Models/`:

- `Element.cs` — идентификатор, имя и тип элемента;
- `Action.cs` — идентификатор, имя и тип действия;
- `State.cs` — статус и сообщение состояния.

Контракт выполнения действий находится в `src/RadishDeck.Core/Execution/`.
Desktop содержит конкретный `ServerStartActionExecutor`, связывающий action
`server.start` с `ServerLauncherService`.

------------------------------------------------------------------------

# 6. Core

Проект:

    RadishDeck.Core

Назначение:

Основная логика приложения.

Содержит:

-   модели;
-   элементы;
-   действия;
-   события;
-   общие интерфейсы.

Core не зависит от:

-   UI;
-   Windows;
-   базы данных.

------------------------------------------------------------------------

# 7. Desktop Application

Проект:

    RadishDeck.Desktop

Назначение:

Windows приложение.

Отвечает за:

-   интерфейс;
-   настройки;
-   запуск клиента;
-   взаимодействие с системой.

Технология:

C# / .NET / WPF

------------------------------------------------------------------------

# 8. Server

Проект:

    RadishDeck.Server

Назначение:

Встроенный сервер.

Отвечает за:

-   API;
-   WebSocket;
-   клиентов;
-   синхронизацию.

Технология:

ASP.NET Core

------------------------------------------------------------------------

# 9. Infrastructure

Проект:

    RadishDeck.Infrastructure

Назначение:

Работа с внешними системами.

Содержит:

-   SQLite;
-   Windows API;
-   Docker API;
-   Plugin loading.

------------------------------------------------------------------------

# 10. Tests

Будущая папка:

    tests/

Содержит:

    tests

    ├── RadishDeck.Core.Tests

    └── RadishDeck.Server.Tests

------------------------------------------------------------------------

# 11. Правила размещения

Запрещено:

-   хранить код в docs;
-   хранить настройки пользователя в src;
-   создавать временные папки в корне.

------------------------------------------------------------------------

# 12. Принцип зависимостей

Правильное направление:

    Desktop

    ↓

    Core


    Server

    ↓

    Core


    Infrastructure

    ↓

    Core

Core является основой системы.

------------------------------------------------------------------------

# 13. Alpha 0.1.0

В Alpha 0.1.0 создаются:

-   Solution;
-   Core;
-   Desktop;
-   Server;
-   Database foundation.

------------------------------------------------------------------------

# 14. Будущее развитие

В следующих версиях:

    plugins/

    clients/

    installer/

    tools/

могут быть добавлены без изменения основной структуры.

------------------------------------------------------------------------

# 15. Главный принцип

Структура проекта должна оставаться:

-   простой;
-   понятной;
-   расширяемой.
