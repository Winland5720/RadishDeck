# RADISH DECK

# PLUGIN SYSTEM

Версия:

Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

Plugin System позволяет расширять возможности Radish Deck без изменения
ядра программы.

Плагин может добавлять:

-   новые элементы;
-   новые действия;
-   новые сервисы;
-   новые источники данных.

Главная идея:

Core Radish Deck остаётся стабильным.

Функции добавляются через плагины.

------------------------------------------------------------------------

# 2. Архитектура плагинов

Общая схема:

    Radish Deck Core

            |

        Plugin Manager

            |

     ----------------------

     |          |          |

    Docker    OBS      System Plugin

------------------------------------------------------------------------

# 3. Требования к плагинам

Каждый плагин должен иметь:

-   название;
-   версию;
-   описание;
-   настройки;
-   список возможностей.

Пример:

    Plugin

    |

    ├── Metadata

    ├── Elements

    ├── Actions

    ├── Services

    └── Settings

------------------------------------------------------------------------

# 4. Plugin Metadata

Каждый плагин содержит информацию:

Пример:

``` json
{
"name":"Docker Plugin",
"version":"1.0.0",
"author":"Radish Deck"
}
```

------------------------------------------------------------------------

# 5. Plugin Elements

Плагин может добавлять свои элементы интерфейса.

Пример Docker Plugin:

Elements:

    Docker Status

    Container List

    Container Resource Usage

Элементы работают через общий Element System.

------------------------------------------------------------------------

# 6. Plugin Actions

Плагин может добавлять действия.

Пример:

Docker:

    docker.start

    docker.stop

    docker.restart

    docker.logs

OBS:

    obs.change_scene

    obs.start_stream

------------------------------------------------------------------------

# 7. Plugin Services

Плагин может работать как сервис.

Примеры:

Docker Service:

-   получение состояния контейнеров.

System Service:

-   получение данных CPU/RAM.

------------------------------------------------------------------------

# 8. Plugin Settings

Каждый плагин может иметь собственные настройки.

Пример:

Docker:

    Docker Host

    Connection

    Timeout

OBS:

    Host

    Port

    Password

------------------------------------------------------------------------

# 9. Plugin Lifecycle

Этапы работы:

    Install

    ↓

    Load

    ↓

    Initialize

    ↓

    Running

    ↓

    Stop

    ↓

    Remove

------------------------------------------------------------------------

# 10. Безопасность

Будущая система должна поддерживать:

-   разрешения;
-   проверку источника;
-   изоляцию;
-   управление доступом.

Особенно для:

-   команд;
-   скриптов;
-   внешних сервисов.

------------------------------------------------------------------------

# 11. Правила разработки

Запрещено:

-   изменять Core из плагина;
-   создавать отдельные системы элементов;
-   создавать собственный Renderer.

Правильно:

Plugin

↓

Element System

↓

Action System

↓

Core

------------------------------------------------------------------------

# 12. Первые плагины

План:

## System Plugin

Функции:

-   CPU;
-   RAM;
-   Disk;
-   Network.

## Docker Plugin

Функции:

-   контейнеры;
-   запуск;
-   остановка;
-   логи.

## OBS Plugin

Функции:

-   сцены;
-   запись;
-   трансляция.

------------------------------------------------------------------------

# 13. Цель Plugin System

Создать платформу, которую можно расширять без изменения ядра.

Radish Deck должен развиваться через:

-   Core updates;
-   Plugin updates.
