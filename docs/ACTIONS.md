# RADISH DECK

# ACTION SYSTEM

Версия:

Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

Action System отвечает за выполнение действий в Radish Deck.

Главная задача:

Связать элемент интерфейса с реальным действием.

Основная цепочка:

    Element

    ↓

    Action

    ↓

    Executor

    ↓

    Result

    ↓

    State Update

------------------------------------------------------------------------

# 2. Главный принцип

Element не должен напрямую выполнять команды.

Неправильно:

    Button

    ↓

    Windows API

Правильно:

    Button

    ↓

    Action

    ↓

    Executor

Это позволяет:

-   использовать одинаковые действия на Desktop/Web/Mobile;
-   добавлять плагины;
-   менять исполнение без изменения интерфейса.

------------------------------------------------------------------------

# 3. Структура Action

Каждое действие содержит:

    Action

    |

    ├── ID

    ├── Name

    ├── Type

    ├── Parameters

    ├── Executor

    └── Result

------------------------------------------------------------------------

# 4. Типы действий

## System Actions

Управление Windows.

Примеры:

Shutdown:

    system.shutdown

Restart:

    system.restart

Lock:

    system.lock

Sleep:

    system.sleep

------------------------------------------------------------------------

# 5. Application Actions

Запуск приложений.

Пример:

    application.start

Параметры:

-   имя;
-   путь;
-   аргументы;
-   рабочая папка.

Пример:

    Steam

    C:\Steam\steam.exe

------------------------------------------------------------------------

# 6. Command Actions

Выполнение команд.

Поддержка:

-   CMD;
-   PowerShell;
-   scripts.

Пример:

    powershell.execute

Параметры:

-   команда;
-   аргументы;
-   права выполнения.

------------------------------------------------------------------------

# 7. Sound Actions

Управление звуком.

Примеры:

    sound.volume

    sound.mute

    sound.device_change

------------------------------------------------------------------------

# 8. Docker Actions

Управление контейнерами.

Примеры:

    docker.start

    docker.stop

    docker.restart

    docker.logs

------------------------------------------------------------------------

# 9. Plugin Actions

Плагины могут добавлять свои действия.

Пример:

OBS:

    obs.change_scene

Discord:

    discord.set_status

------------------------------------------------------------------------

# 10. Action Parameters

Каждое действие может иметь параметры.

Пример:

Запуск программы:

``` json
{
"path":"C:\\Program\\app.exe",
"arguments":"--start"
}
```

Docker:

``` json
{
"container":"nginx"
}
```

------------------------------------------------------------------------

# 11. Executor

Executor отвечает за реальное выполнение.

Примеры:

System Executor:

    Windows API

Application Executor:

    Process Start

Docker Executor:

    Docker API

------------------------------------------------------------------------

# 12. Result

После выполнения действие возвращает результат.

Примеры:

Успешно:

    success

    message:
    Application started

Ошибка:

    failed

    message:
    Application not found

------------------------------------------------------------------------

# 13. State Update

После выполнения действия обновляется состояние.

Пример:

До:

    Docker

    Stopped

После:

    Docker

    Running

------------------------------------------------------------------------

# 14. Events

Action может создавать события.

Примеры:

    action_started

    action_completed

    action_failed

------------------------------------------------------------------------

# 15. Безопасность

Будущая система должна поддерживать:

-   разрешения;
-   подтверждение опасных действий;
-   права пользователей.

Пример:

Shutdown:

    Require confirmation:
    YES

------------------------------------------------------------------------

# 16. Правила разработки

Запрещено:

-   хранить команды внутри кнопок;
-   создавать отдельную логику для каждого клиента;
-   выполнять действия напрямую из UI.

Правильно:

    Element

    ↓

    Action

    ↓

    Executor

------------------------------------------------------------------------

# 17. Цель Action System

Создать универсальную систему выполнения.

Один Action должен работать через:

-   Desktop;
-   Web;
-   Mobile;
-   Plugins.

Главная идея:

Интерфейс говорит ЧТО сделать.

Action System решает КАК сделать.
