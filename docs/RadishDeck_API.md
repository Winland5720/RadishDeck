> План API по Architecture v3. Desktop Designer создаёт проект, Server предоставляет API и выполняет действия, Web Runtime отображает Deck общим Renderer. Примеры маршрутов ниже не являются перечнем реализованных endpoints.

# RADISH DECK

# API DOCUMENTATION

Версия: Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

API отвечает за взаимодействие между:

Radish Deck Desktop → API → Radish Deck Client

Используется для: - получения страниц; - получения элементов; -
управления состоянием; - выполнения действий; - подключения клиентов.

------------------------------------------------------------------------

# 2. Общая архитектура

Radish Deck использует:

## REST API

Для получения данных, изменения настроек и управления объектами.

## WebSocket

Для событий в реальном времени, обновления состояния и синхронизации
клиентов.

------------------------------------------------------------------------

# 3. Base URL

Клиент получает адрес сервера динамически.

Пример:

http://`<RADISH_DECK_IP>`{=html}:8080

Для удалённого клиента используется выбранный доступный IP сервера. Loopback допустим только для локального доступа. Адрес не зашивается в код клиента.

------------------------------------------------------------------------

# 4. Server Status

GET /api/status

Ответ:

{ "status":"running", "version":"0.1.0", "clients":1 }

------------------------------------------------------------------------

# 5. Configuration API

GET /api/settings

POST /api/settings

Настройки: - IP; - Port.

------------------------------------------------------------------------

# 6. Pages API

GET /api/pages

GET /api/pages/{id}

Страница содержит: - название; - элементы; - layout.

------------------------------------------------------------------------

# 7. Elements API

GET /api/pages/{id}/elements

Элемент содержит: - type; - name; - grid_x; - grid_y; - grid_width; -
grid_height.

------------------------------------------------------------------------

# 8. Element CRUD

POST /api/elements

PUT /api/elements/{id}

DELETE /api/elements/{id}

------------------------------------------------------------------------

# 9. Actions API

GET /api/actions

Примеры действий: - open_application; - shutdown; - restart; -
volume_change; - docker_restart.

------------------------------------------------------------------------

# 10. Execute Action

POST /api/actions/{id}/execute

------------------------------------------------------------------------

# 11. System Monitoring API

GET /api/system/status

Данные: - CPU; - RAM; - температура; - диски; - сеть.

------------------------------------------------------------------------

# 12. Applications API

GET /api/apps

Хранится: - название; - путь; - аргументы; - иконка.

------------------------------------------------------------------------

# 13. Docker API

GET /api/docker

Команды: - Start; - Stop; - Restart; - Logs.

------------------------------------------------------------------------

# 14. Clients API

GET /api/clients

Типы: - desktop; - web; - mobile; - tablet.

------------------------------------------------------------------------

# 15. WebSocket

Подключение:

ws://`<IP>`{=html}:8080/ws

Используется для: - обновления интерфейса; - событий; - команд.

------------------------------------------------------------------------

# 16. WebSocket Events

Типы событий: - client_connected; - layout_update; - state_update; -
execute.

------------------------------------------------------------------------

# 17. Ошибки

Формат:

{ "success":false, "error":"message", "code":400 }

------------------------------------------------------------------------

# 18. Версионирование API

Использовать:

/api/v1/

------------------------------------------------------------------------

# 19. Безопасность

Будущие возможности: - pairing; - токены; - авторизация; - права
клиентов.

------------------------------------------------------------------------

# 20. Главный принцип API

API не должен знать тип клиента.

Один API используется для: - Desktop; - Web; - Mobile; - Tablet.

Сервер предоставляет данные.

Клиент отвечает за отображение.
