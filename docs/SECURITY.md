> Целевые требования безопасности. Pairing, permissions и другие будущие механизмы вводятся отдельными этапами; их описание не означает наличие в текущем прототипе.

# RADISH DECK

# SECURITY DOCUMENTATION

Версия:

Alpha 0.1.0

------------------------------------------------------------------------

# 1. Назначение

Security System отвечает за безопасность Radish Deck.

Главная задача:

Защитить компьютер от несанкционированного управления.

Radish Deck имеет доступ к:

-   запуску программ;
-   выполнению команд;
-   управлению системой;
-   изменению настроек.

Поэтому безопасность является обязательной частью архитектуры.

------------------------------------------------------------------------

# 2. Основные принципы

Безопасность строится вокруг:

-   доверенных клиентов;
-   разрешений;
-   подтверждений действий;
-   журналирования.

------------------------------------------------------------------------

# 3. Клиенты

Каждое устройство должно быть зарегистрировано.

Примеры:

-   телефон;
-   планшет;
-   браузер;
-   другой ПК.

Клиент имеет:

    Client

    |

    ├── ID

    ├── Name

    ├── Type

    ├── Token

    ├── Status

    └── Last Seen

------------------------------------------------------------------------

# 4. Pairing

Перед первым подключением клиент должен пройти регистрацию.

Процесс:

    Client

    ↓

    Request Pairing

    ↓

    User Confirmation

    ↓

    Generate Token

    ↓

    Client Authorized

После pairing клиент получает доступ.

------------------------------------------------------------------------

# 5. Client Token

Каждый клиент использует уникальный токен.

Токен используется для:

-   идентификации;
-   проверки доступа;
-   восстановления подключения.

Токены нельзя хранить в открытом виде.

------------------------------------------------------------------------

# 6. Permissions

Будущая система прав.

Пример:

Client:

Phone

Разрешения:

    Allowed:

    ✓ View Status

    ✓ Control Sound


    Denied:

    ✗ Shutdown PC

------------------------------------------------------------------------

# 7. Опасные действия

Некоторые действия требуют подтверждения.

Примеры:

Shutdown:

    Are you sure?

    [Confirm]

Удаление данных:

    Require confirmation

------------------------------------------------------------------------

# 8. Action Security

Каждое действие должно проверяться.

Поток:

    Client

    ↓

    Permission Check

    ↓

    Action Validation

    ↓

    Executor

    ↓

    Result

------------------------------------------------------------------------

# 9. Network Security

Radish Deck должен:

-   показывать доступные сетевые интерфейсы;
-   позволять выбрать IP;
-   позволять изменить Port.

Для удалённых клиентов и LAN-проверок используется выбранный доступный IP сервера. Loopback допустим для локального запуска и изолированных проверок, но не проверяет доступ с другого устройства.

------------------------------------------------------------------------

# 10. API Security

Будущие возможности:

-   API tokens;
-   authentication;
-   rate limiting;
-   HTTPS.

------------------------------------------------------------------------

# 11. Logs

Все важные события должны записываться.

Примеры:

    Client connected

    Action executed

    Permission denied

    Server started

------------------------------------------------------------------------

# 12. Plugin Security

Плагины могут выполнять код.

Поэтому:

-   проверять источник;
-   ограничивать права;
-   хранить настройки отдельно.

------------------------------------------------------------------------

# 13. Backup Security

Защищать:

-   настройки;
-   профили;
-   layout;
-   действия.

Поддерживать:

-   backup;
-   restore.

------------------------------------------------------------------------

# 14. Правила разработки

Запрещено:

-   выполнять команды без проверки;
-   доверять неизвестным клиентам;
-   хранить пароли открыто;
-   обходить систему разрешений.

------------------------------------------------------------------------

# 15. Цель Security System

Radish Deck должен быть:

-   удобным;
-   мощным;
-   безопасным.

Главный принцип:

Пользователь должен контролировать, какие устройства и действия имеют
доступ к компьютеру.
